# 로컬 네트워크 진단 로그

추가일: 2026-10-26

기존 AWS 기록과 날짜_model.log의 저장 방식을 유지한다. Electron 메인 프로세스에서 독립적인 비동기 진단을 실행한다.

## 저장 및 보관

- 기존 electron-log 파일과 같은 디렉토리에 YYYY-MM-DD_network.log를 UTF-8 텍스트로 저장한다.
- 날짜는 PC 로컬 시간 기준이며 자정 이후 새 파일로 기록한다.
- 시작 및 날짜 변경 시 90일보다 오래된 일별 network.log 파일만 삭제한다. 기존 model.log와 매출은 삭제하지 않는다.
- AWS에 진단 로그를 업로드하지 않는다. 토큰, 비밀번호, 카드정보, 응답 본문을 수집하지 않는다.

## 기록 항목

- 시작: 프로그램 버전, PID, OS 가동 시간, 추정 OS 부팅 시각. 프로그램 재실행과 PC 재부팅을 비교하는 단서다.
- 최초/설정 변경: 어댑터 이름, IPv4, 게이트웨이, DNS, DHCP 설정.
- 진단: localhost:3142/health, 환경별 API 호스트 DNS, Cloudflare 터널 SRV DNS, 외부 API origin HTTP 도달 여부, 게이트웨이 ICMP 결과와 소요 시간.
- 외부 origin의 403/404는 서버에 도달한 결과이며 업무 API나 결제가 정상이라는 뜻은 아니다. ICMP 무응답도 인터넷 단절로 단정하지 않는다.
- 장애 감지 및 복구: 측정 결과와 장애 지속 시간. 네트워크 장애와 로컬 API 오류를 함께 기록하되 원인을 자동 단정하지 않는다.

## 빈도와 영향

- 1분마다 진단. 터널 헬스체크 실패 시에도 요청하되 1분 내 중복과 진행 중 중첩은 막는다.
- 정상 요약 30분, 장애 지속 요약 5분. 설정 변경과 장애 시작/복구는 다음 진단에서 기록한다.
- 프로세스 호출과 파일 저장은 비동기이며 진단에는 제한 시간을 둔다. 결제, 제조, 재시작, DNS 설정은 조작하지 않는다.
- PC 종료/강제 종료 직전 마지막 로그는 보장되지 않는다. 진단 주기보다 짧은 장애는 누락될 수 있다.

## 검증

`node --test tests/networkMonitor.test.cjs`

DNS 실패/지속/복구, 중복 억제, 민감 URL 제거, 90일 삭제 범위, 설정 수집 실패 및 로컬 API 오류를 모의 검증한다.
Windows 어댑터 정보 수집과 실제 텍스트 파일 생성도 확인했다. 매장 실기기의 통신 장애 재현 및 설치본 테스트는 별도 필요하다.
# 어댑터 사용량

Windows의 Get-NetAdapterStatistics로 어댑터별 수신·송신 누적 바이트와 약 5분간 증가량을 별도 네트워크 로그에 기록한다. 프로그램 전체 합계이며 cloudflared 개별 사용량이나 라우터의 다른 기기는 구분하지 않는다. 최초 측정, 재시작, 어댑터 교체 또는 카운터 감소 시에는 기준점만 기록하며 증가량은 null이다. 실제 집계 간격은 intervalMs를 확인한다. 카운터의 누적 시작 시점은 Windows/드라이버에 따라 달라 청구 월 사용량을 뜻하지 않는다.
